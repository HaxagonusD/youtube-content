Video Script — Full Draft

I'm Unemployed.
So I Hired an AI
to Get Me Hired.

Hook

[X] job applications. Zero hours of my time.

I built a system that finds jobs, rewrites my resume for each one, and applies — while I sleep.

I haven't opened LinkedIn in a week.

Frame

I built this in a weekend with Claude Code — and I mean Claude actually designed the architecture, not just wrote the code.

By the end of this video you'll see exactly how it finds jobs, tailors my resume to each one, applies, and fixes itself when it breaks.

And after watching, you'll probably want to build one too.

Tension

Here's the thing though.

When you see a build like this, you probably assume the impressive part is the AI — the so-called "intelligence" picking jobs and rewriting the resume.

That's wrong.

The LLM is the easy part. OpenRouter plus a prompt does the resume tailoring in twenty lines of code. Anyone watching this could ship that on a Saturday.

The hard part — the part that makes this an actual system instead of a demo — is what happens at 3 AM when LinkedIn changes a button and your script silently breaks for a week before you notice.

That's the part nobody builds. That's why every "AI agent" you've seen on Twitter looks magical for 90 seconds and then dies the second it touches a real website.

The intelligence isn't the moat. The loop is.
Beat 1It finds the jobs

First problem — finding jobs is the worst part of being unemployed.

While I was making coffee this morning, it had already pulled the day's listings from LinkedIn — exactly the kind of role I'd search for myself. Then it did the same thing on Indeed.

Greenhouse is next. Each platform I add is one more module hitting the same queue. It compounds.

Beat 2It tailors the resume

A tailored resume makes you 6 times more likely to land an interview. That's not a tip — that's from 3.2 million applications.

Here's where most people stop. They paste the job description into ChatGPT, get a tailored resume back, copy it over. Fine for one job. But you can't do that 50 times a day.

So I had Claude wire up the rewrite. Take this listing — they wanted distributed systems experience. The model found the bullet on my resume that matched, pulled it to the top, and rewrote it in the exact language they used.

Same resume going in, hundreds of versions coming out, one for each job.

Beat 3It applies

Now the part that actually saves time.

Watch this. It opens the application page, walks through the form, hits submit — about twelve seconds, start to finish. The confirmation page screenshots to a log with a timestamp, so I can prove it actually went through.

That log matters in a second.

Beat 4It fixes itself — climax

Here's the part that broke my brain.

And this is the part nobody builds.

So I gave Claude Code access to the logs.

This happened on day three. LinkedIn changed a button selector. The applier crashed.

The log caught it. Claude Code read it, figured out what broke, and fixed the function. The next application went through.

No human in the loop. I was asleep.

I went to sleep with broken code. Woke up with working code. Nobody touched it.

Beat 5The dashboard

Last piece. I needed to actually see what this thing was doing.

Every job it applies to gets a card. Title, company, link to the listing, the resume version it sent, screenshots of every step. All timestamped.

And then the part I actually look at every morning.

A heatmap. Same idea as the GitHub contribution graph, but for applications. Dark green squares are heavy days. Light squares are light days. Empty squares mean something broke — and I check the logs to see why.

I don't read the dashboard to manage the system. I read it to trust the system.

Because if you're going to let an AI run your job search, you need to be able to see exactly what it did when you weren't looking.

PayoffClose the loop

So — did it work?

[X] applications submitted. [Y] hours of my time. The system has been running for [Z] days and I haven't touched it.

But honestly — that's not the part of this that matters.

PayoffCrystallize

Most AI agents fail because nobody builds the loop around them. The model isn't the bottleneck.

AI stopped being a tool the day it started fixing its own bugs.

PayoffNext move

If you can write code, open Claude Code tonight.

Build the dumbest version of this you can — one job board, no resume tailoring, nothing fancy.

But build the loop. Make it log everything. Make it catch its own errors. Make it heal itself when something breaks. That's the part you have to feel work to understand.

The people who build these systems are going to be fine. Be one of them.

Post 01 Written post · 300–500 words Strong

I'm unemployed. So I built an AI that applies to jobs while I sleep.

Full post text

I'm unemployed. So I built an AI that applies to jobs while I sleep.

Not a script that fills out a form. A system — one that finds jobs, rewrites my resume to match each one, submits, and fixes itself when it breaks.

[X] applications submitted. [Y] hours of my time.

Here's what I actually learned building it.

The model is the easy part.

Tailored resumes make you 6x more likely to land an interview — that stat is from 3.2 million applications. Wiring up an LLM to do the rewriting took me about 20 lines of code. Anyone reading this could ship that on a Saturday afternoon.

The hard part is what happens at 3 AM when LinkedIn changes a button and your script silently breaks for a week before you notice.

Every "AI agent" I've seen fails here. The demo looks clean for 90 seconds. Then it touches a real website, gets a DOM change it didn't expect, and dies quietly.

So I built the loop around the model instead.

Every step logs to a file. Every failure surfaces to a queue that Claude Code reads, diagnoses, and patches before the next run. Day three of running it, LinkedIn moved a button selector. The system caught it, rewrote the failing function, and the next application went through.

I was asleep.
